**文档版本**：v2.2 (AI Deferred / Security First)
**日期**：2026-05-27
**状态**：**架构收敛期（Architecture Convergence）**

---

## 1. 项目概述

**项目名称**：MusKitty 核心 (MusKitty Core)
**项目代号**：Project Aurora（极光）
**项目性质**：**原生 AI 浏览器内核（Native AI Browser Kernel）**
**当前状态**：**架构设计与核心模块 Rust 化启动阶段（AI 能力暂不实现）**

### 1.1 核心愿景
打造全球首个 **“Rust 内存安全基座 + 端侧原生 AI 推理”** 的浏览器内核。
我们不仅是为了修补 Chromium 的内存安全漏洞，更是为了彻底重构浏览器与 AI 的关系：**让 AI 不再是外接插件，而是浏览器的原生神经系统。**

> **[战略注记]**：基于当前无代理的开发环境与工程化考量，**Phase 1 至 Phase 2 将暂不涉及具体 AI 推理代码编写、大模型对接或多模态分析**。我们将全力聚焦于构建稳固的 Rust 安全基座，并预留标准化的 AI 接入接口。

### 1.2 为什么叫 "MusKitty"？
*   **Mus**：Memory Safety（内存安全） + **M**ultimodal **U**nderstanding（多模态理解）。
*   **Kitty**：轻盈、敏捷、独立生存（无需云端亦可运行）。

### 1.3 核心理念：赋能，而非取代
AI 应该作为人类能力的延伸，在完全透明和可控的前提下工作。MusKitty 的每一次点击、每一次输入、每一次导航，都会明确征得用户同意。

> **猫咪很聪明，但缰绳永远在您手中。**

## 2. 战略定位：什么是“原生 AI 浏览器”？

### 2.1 与传统浏览器的区别

| 维度 | 传统浏览器 (Chrome/Edge) | MusKitty Core |
| :--- | :--- | :--- |
| **AI 位置** | 云端 API / 独立进程插件 | **内核级集成 (In-Process / Mojo IPC)** |
| **感知能力** | 仅能获取 DOM 文本 | **原生视觉理解 (像素级) + 语义理解** |
| **隐私策略** | 数据上传云端 | **端侧推理优先 (On-Device First)** |
| **交互模式** | 点击、输入 | **Agentic (自主任务执行)** |
| **安全基石** | C++ (漏洞百出) | **Rust (内存安全)** |

### 2.2 核心目标
- 拟人化操作 — 超越简单 API 调用，能识别页面元素，像真人一样思考操作逻辑
- 用户主权 — 所有关键操作步骤均会暂停，清晰说明动作意图，等待明确许可
- 自然语言任务 — 直接用自然语言描述目标
- 强大的上下文理解 — 结合页面 DOM、视觉布局和文本内容
- 模块化与可扩展 — 核心引擎与任务技能分离

### 3.2 关键设计决策
*   **Rust 作为 AI 宿主**：所有的模型加载、推理调度、张量计算都在 Rust 侧完成，避免 C++ 的内存漏洞污染 AI 执行环境。
*   **Mojo 作为神经突触**：AI Core 与渲染引擎通过 Mojo 通信。例如，AI 需要“看到”页面，不是截屏发过去，而是通过 Mojo 请求渲染树的语义快照。
*   **AI 能力“冷冻”策略**：在 `//third_party/muskitty/ai/` 目录下仅定义 **Trait（特征）** 和 **数据结构**，不包含任何具体模型推理实现，确保编译环境纯净。

### 3.4 核心模块

#### 任务解析层 (core/task)
将用户的自然语言目标解析为结构化的可执行任务序列：

```
用户: "比较这三款耳机的价格和评价"
  → 解析为:
    1. 搜索三款耳机产品页
    2. 提取每款的价格、评分、评论数
    3. 生成对比表格
    4. 呈现结果并等待用户决策
```

#### 页面感知层 (core/perception)
多模态理解页面状态，做出合理决策：
- **DOM 分析** — 解析页面结构，识别表单、按钮、链接等可交互元素
- **视觉分析** — 理解页面布局，判断元素可见性和视觉层次
- **上下文建模** — 结合历史操作和当前状态，构建页面上下文

#### 动作执行层 (core/action)
拟人化网页操作，模拟真实用户行为：
- 点击（含可见性检测、等待加载）
- 键盘输入（含输入法、快捷键支持）
- 页面滚动（渐进式、目标定位）
- 页面导航与标签页管理

#### 技能系统 (skills)
核心引擎与领域技能分离，支持热加载：
- 内置技能：表单填写、搜索聚合、商品对比、信息提取
- 自定义技能：用户或开发者可扩展特定网站的专用技能
- 技能注册表：发现、加载、管理第三方技能包

#### 安全沙箱 (safety)
多层防护保障用户安全与隐私：

| 层级 | 机制 | 说明 |
|------|------|------|
| 域名授权 | 白名单/黑名单 | 精确控制可访问的网站范围 |
| 操作确认 | 暂停-授权模式 | 关键操作需用户明确批准 |
| 审计日志 | 全量记录 | 所有操作可追溯、可复盘 |
| 本地优先 | 数据不出本地 | 敏感信息尽可能本地处理 |

### 3.5 交互流程

```
用户发起任务
    ↓
MusKitty 解析任务 → 拆分为步骤序列
    ↓
对每个步骤:
    ├─ 分析当前页面状态
    ├─ 规划具体操作
    ├─ 向用户呈现操作意图 → "我将要点击'加入购物车'按钮"
    ├─ 等待用户决定: 批准 / 跳过 / 中断
    └─ 执行操作 → 记录日志
    ↓
任务完成 → 呈现结果摘要
```

### 3.6 关键设计原则
1. 透明性 — 每一步意图清晰可读，不隐藏任何操作
2. 可中断性 — 用户随时可以暂停、跳过或终止
3. 渐进式信任 — 用户可为信任网站设置操作免确认
4. 模块化 — 技能独立于引擎，社区可贡献技能包

## 4. 实施路线图

### Phase 1: The Foundation (当前阶段)
**目标：安全底座 + 基础设施**
*   **Rust 化**：`//crypto/`, `//net/` (基础), `//base/` (工具类)。
*   **AI 准备**：**仅集成 `candle` 或 `burn` 作为 Rust ML 基础库依赖（不启用训练，仅保留库文件，不调用）**。
*   **成果**：编译出带有 Rust Crypto 的 `chrome.dll`，且代码结构中包含 AI 模块的占位符。

### Phase 2: The Senses (感知能力)
**目标：让浏览器“看懂”网页**
*   **重写 Media Pipeline**：用 Rust 重写 `//media/` 解析部分，集成 `image-rs`, `rav1e` (AV1)。
*   **OCR & Vision**：**暂不集成 `tesseract-rs` 或 CV 库，仅预留接口**。
*   **成果**：浏览器能在不依赖 JS 的情况下提取页面中的文字和图像语义（通过纯解析库）。

### Phase 3: The Brain (智能内核)
**目标：端侧模型集成**
*   **LLM Runtime**：**暂不集成 GGUF 模型加载器**。
*   **RAG 引擎**：**暂不构建向量数据库**。
*   **成果**：代码层面支持 AI 调用，但无实际推理能力。

### Phase 4: The Agent (自主代理)
**目标：AI 操作浏览器**
*   **Action Model**：**暂不训练/微调模型**。
*   **权限沙箱**：利用 Rust 的沙箱能力，限制 AI 只能访问特定的 DOM 节点。
*   **成果**：定义 AI 操作浏览器的标准协议。

### Phase 5 — 进阶功能
- 复杂多页流程任务（如"完成整个购物流程"）
- 视觉对比与验证（确认操作结果是否符合预期）
- 长期记忆与用户偏好学习
- 错误恢复与自动重试
- 跨会话任务恢复

### Phase 6 — 生态与发布
- 技能开发 SDK 与文档
- 技能市场/社区上线
- 跨平台支持（Windows / macOS / Linux）
- 浏览器扩展版（轻量版）
- 多语言自然语言支持

### 里程碑
- v0.1.0 — 原型：基础浏览器 + 单步操作 + 确认面板
- v0.2.0 — 感知：DOM + 视觉分析 + 自然语言任务解析
- v0.3.0 — 技能：技能系统就绪 + 内置技能集
- v0.4.0 — 安全：完整沙箱 + 审计 + 隐私保护
- v1.0.0 — 正式版：全功能 + 技能市场 + 跨平台

## 5. 技术栈选型 (AI Native)

| 领域 | 技术选择 | 理由 |
| :--- | :--- | :--- |
| **ML Framework** | **Candle** (首选) / Burn | 纯 Rust，无 Python 依赖，支持 CUDA/Metal。**（当前仅作依赖保留，不调用）** |
| **Image/Video** | `image-rs`, `rav1e` | 纯 Rust 编解码，安全 |
| **Vector DB** | `surrealdb` / `tantivy` | Rust 生态，嵌入式。**（暂不集成）** |
| **NLP/Tokenizers** | `tokenizers` (HuggingFace) | 工业级标准。**（暂不集成）** |
| **Build System** | `gn` + `ninja` | Chromium 原生 |
| **FFI** | `cxx` | 官方推荐，类型安全 |
| **浏览器协议** | CDP (Chrome DevTools Protocol) | 主流，功能最全 |
| **技能系统** | WASM / JS Plugin | 跨语言、安全沙箱 |

## 6. 环境与约束

*   **网络环境**：无代理。采用 **“一次性外带，永久离线”** 策略。需提前下载好所有 Rust Crates 缓存 (`~/.cargo/registry`) 和 Chromium 依赖。
*   **硬件目标**：
    *   **PC 端**：支持 NVIDIA GPU (CUDA) 和 Apple Silicon (Metal) 加速。
    *   **内存**：最低 16GB RAM（用于加载 7B-8B 量化模型）。
*   **输出物**：最终产出为 **`muskitty.dll`** (Windows) 或 **`libmuskitty.so`** (Linux)，作为新浏览器的核心。

## 7. 风险与挑战

| 风险 | 应对方案 |
| :--- | :--- |
| **AI 库体积过大** | 仅集成推理能力，裁剪训练代码；模型文件不打包进安装包，按需下载。 |
| **Rust 编译速度** | 使用 `sccache`，拆分 Workspace，避免过度泛型化。 |
| **与 Chromium 上游冲突** | 尽量将 AI 代码放在 `//third_party/muskitty/`，减少对 `//chrome/` 的直接侵入。 |
| **模型版权/合规** | 使用 Apache 2.0 / MIT 许可的开源模型（如 Phi-3, Mistral）。 |
